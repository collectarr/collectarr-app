# Kind registration and generated artifacts

Collectarr keeps its application kind registry as explicit, manually maintained
Dart source. The composition root is
`lib/features/library/kinds/registry/collectarr_kind_registry.dart`; it makes
kind wiring and dispatch visible in code. It is not generated by a source-tree
discovery step.

## Kind registry generation

`tool/generate_kind_registries.dart` generates only these repetitive artifacts:

- `lib/features/library/kinds/registry/collectarr_kind_database_tables.g.dart`,
  which composes kind-owned Drift table types for `LocalDatabase`;
- `lib/dev/seeds/collectarr_dev_seed_registry.g.dart`, which composes typed
  development seed contributors.

The generator does not create the application kind registry, kind page or
module registrations, routes, capability registrations, or provider dispatch.
Those remain explicit source. Run the generator after changing a kind's local
Drift tables or development seed contributors:

```text
dart run tool/generate_kind_registries.dart
```

## Other generated files

The ownership manifest is generated separately by
`tool/generate_kind_field_ownership.dart`. It writes
`tool/architecture/generated/kind-field-ownership.json` from Drift columns,
kind-local mapper aliases, and kind-owned workspace field declarations. It is
an architecture inventory, not a registration source.

Drift's generated database code is produced separately by `build_runner`:

```text
dart run build_runner build --delete-conflicting-outputs
```

CI runs these generation steps independently and checks that generated files are
up to date. The distinction is intentional: the kind registry is reviewed
application source, while the generators produce mechanical table/seed
composition, the ownership manifest, and Drift implementation code.
