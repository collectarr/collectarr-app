# Flattened Catalog Reference Inventory (App)

This inventory records the current App feature surfaces that carry a Work/Release/Copy identity or personal data. The destinations below preserve the existing feature where it represents useful user data. They do not claim the migration code is complete.

The pinned kind-owned Catalog Item field contract is tool/core_contracts/catalog-item-v1.json. After updating it from Core with tool/update_core_contracts.ps1, regenerate App's field-name projection with dart run tool/generate_catalog_item_v1_fields.dart. The generated file carries the pinned schema hash and is checked in CI.

The Music ledger is `music-catalog-field-inventory.md`. The provisional ledgers for Anime, Board Game, Book, Comic, Game, Manga, Movie, and TV are in `catalog-item-field-ledgers/`. Their Core/App keys and schema types are recorded, but their displayed labels, edit tabs, repeat behavior, and CLZ parity remain unverified until the corresponding Edit-form captures are available.

## Personal-reference migration rule

The current kind-owned copy rows retain their own IDs and commonly contain both a broad `catalogRef` and a more specific `targetRef`. An explicit concrete target maps directly to one flattened root. A reference only to a parent with no concrete child can preserve that parent ID as a root. A parent-only reference with multiple candidate concrete children is unresolved and must be reported for explicit resolution; it must never be duplicated across candidates or assigned to an arbitrary “primary” child.

The example cases are in `fixtures/flattened_personal_reference_cases.json`. Before removing any corresponding implementation, add kind-specific field and identity cases for every storage table and verify all existing consumers have moved to the destination above.
