# Reproducible Music inspector comparison

The fixture `tool/fixtures/music_inspector_reference.json` describes the saved
**Collectarr Inspector Reference** album. Its Core ID is
`657cf11a-3fa8-577d-9d36-20280ec4aca4`; its local entry ID is
`beba4847-5ae5-550a-bde8-1109394ec355`.

The live CLZ counterpart was manually populated through the authenticated
editor on 2026-10-11, item **17050856**. It has front/back covers, edition data,
Vinyl technical/recording data, contributors with an instrument, a track and
composition, rating, ownership/purchase data, notes/tags/link, one listening
event, an active Alex Reference loan and a returned Jane Reference loan.
Only that new comparison item and its new reference picklist values were edited.

## Local Windows seed

Run from the App repository, naming the actual database explicitly:

```powershell
flutter run -d windows -t scripts/seed_music_comparison.dart --dart-define=COLLECTARR_REFERENCE_DB=C:/path/collectarr-library.sqlite
```

The seed upserts the one stable entry in a transaction and inserts its local
cover bytes, location, disc storage, listening event and two loan records.
Repeating it resets the reference item's fixture values and attachments; it
never clears or rewrites unrelated entries. ID/title collisions fail. Its return
value is reread after location attachment so subsequent edits retain that data.
The test covers repeatability, attachments, loans and collision refusal.

For this comparison it was run against the configured local database at
`C:/Users/saita/Documents/collectarr-library.sqlite`. Browser verification used
an isolated SQLite/IndexedDB copy of the same fixture, not the user's browser DB.

## Core PostgreSQL seed

Run in the Core repository with its configured Python environment:

```powershell
$env:PYTHONPATH = (Get-Location).Path
.venv/Scripts/python.exe ../collectarr-app/scripts/seed_music_comparison_core.py --validate-only
.venv/Scripts/python.exe ../collectarr-app/scripts/seed_music_comparison_core.py --database-host 127.0.0.1 --database-name collectarr_music_ui_reference
```

Create the named comparison database first. For a database with no public
tables, `--initialize-empty` creates the current Core model schema. It explicitly
refuses to reshape an existing schema. The actual comparison database is
**collectarr_music_ui_reference** in the local PostgreSQL container; the older
default database was left intact. Credentials come from Core configuration and
are never printed. The script validates the strict response contract and checks
every persisted canonical field after committing.

Core cover URLs point to the optional local fixture host:

```powershell
python -m http.server 8770 --bind 127.0.0.1 --directory tool/fixtures
```

The local App seed also stores the image bytes, so its covers work offline.
The PNGs are original procedural comparison artwork. No CLZ cover artwork or
font binaries are distributed.

## Domain and comparison limits

Edition metadata stays at album scope. Recording metadata and disc credits stay
at disc scope. Credits use optional contributor references and instrument lists;
composition belongs to the track. The fixture deliberately does not recreate
CLZ's root recording/role arrays, artificial person IDs or packed extras.

`music_inspector_mixed_reference.json` is an alternative isolated mixed-disc
fixture for canonical-domain tests. It must not be seeded over the primary
reference identity in a shared database.

The CLZ record's Added/Modified timestamps are generated by CLZ. The local
fixture has deterministic timestamps. CLZ uses its own role grouping and may
choose Composer as the inspector's primary creator; Collectarr retains the
canonical artist and scoped generic credits. These are explicit differences,
not hidden compatibility conversions.
